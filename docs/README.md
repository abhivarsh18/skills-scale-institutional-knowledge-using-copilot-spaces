# OctoAcme Project Management Docs

Welcome to the OctoAcme Project Management documentation hub. This folder contains our project management processes, templates, and best practices used across cross-functional projects. The docs are living artifacts intended to centralize process knowledge, improve onboarding, reduce single‑person dependencies, and provide a single entry point to the OctoAcme delivery approach.

Overview
OctoAcme follows a structured, phase‑based lifecycle: Initiation, Planning, Execution & Tracking, Release & Deployment, and Retrospective & Continuous Improvement. Projects start with a one‑pager to align goals, scope, stakeholders, and success criteria. Planning creates a prioritized backlog and release plan; execution relies on regular cadences (daily standups, backlog refinement) and clear acceptance criteria; releases follow standardized checklists and rollback/runbook steps; retrospectives capture learnings and drive process improvements.

Key Workflows & Practices
- Initiation: Create a project one‑pager, identify stakeholders, and set success metrics before committing work.
- Planning: Break work into shippable increments, estimate, manage dependencies, and maintain a prioritized backlog.
- Execution & Tracking: Use daily standups, weekly status updates, and CI checks. Maintain a risk register and surface blockers in weekly delivery syncs.
- Release & QA: Enforce quality gates with automated testing and pre‑release checklists. Coordinate rollouts and maintain rollback plans.
- Continuous Improvement: Run retros after sprints/releases/incidents; track action items and close them in follow‑ups.

Roles & Personas (quick reference)
- Project Manager: Coordinates delivery, manages schedules, risks, and communications.
- Product Manager: Defines outcomes, prioritizes the backlog, and measures success.
- Developers: Implement features, collaborate on design and quality.
- QA / Test Engineers: Own test strategy, automation, and acceptance testing.
- Stakeholders: Provide inputs, approvals, and business context.

Communication Cadence
- Daily: Team standups (15 minutes) — progress, blockers, dependencies.
- Weekly: PM + Product Manager sync, delivery team sync, risk review.
- Milestone: Demo/Review at the end of each sprint or milestone.
- Monthly: Stakeholder updates.
- Ad‑hoc: Escalation paths for urgent issues.

Getting started
- New team members: Start with the Project Management Overview, then follow the onboarding checklist and role-specific docs.
- Launching a project: Follow Initiation → Planning → Execution flow and use templates for one‑pagers, risk registers, and release plans.
- Delivery & support: Use Execution & Tracking for daily management and Risk Management for escalations; run retros to capture improvements.

How to contribute
- Suggest changes via pull requests or open an issue referencing the appropriate doc.
- Maintain the docs in this folder as living artifacts; update runbooks and checklists as processes evolve.
